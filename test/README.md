# Checks

The game is one self-contained HTML file with no build step, so the suite
drives the real thing in a real browser rather than importing pieces of it.
Each check boots a fresh page, does something to it, and asserts on what came
back. Any console error or uncaught exception during a check fails it, whether
or not the check was looking for one.

## Running them

```sh
npm install
npx playwright install chromium     # once
npm test
```

```sh
npm test                 # everything
node test/run.js render  # only checks whose name contains "render"
node test/run.js --shots # also write PNGs to test/shots/
```

Non-zero exit on failure, so it drops into CI unchanged.

## Playing it locally

```sh
npm start                # http://localhost:8080
```

Open `index.html` straight off the disk and the browser treats `file://` as an
opaque origin, which blocks `localStorage`: the game runs but never saves, and
the failure is silent. Always play it over http.

## What is checked, and why

| check | what would break without it |
| --- | --- |
| `smoke` | The only check that asserts on the game as a whole: `derive()` returns finite non-negative numbers, the canvas paints something and keeps changing, all ten screens render the row counts their data tables say they should, the loop earns and cards a hole, a wager starts and pays, and the result reaches the save. If this fails nothing below it means anything. |
| `render` | Every course in every weather and every wager book floor draws, and the ground pass stays in budget. Themes are authored as literal tables in places, so a colour the renderer newly depends on can be missing on exactly one course — which is how the wager book went down on its first frame once. Also that nothing draws a hard line across the frame: the sky and the ground have to meet at the horizon without a step, and the haze over them has to keep its shape on a tall buffer as well as a short one. Each scene is timed on the second slowest of its last sixteen frames: the slowest failed once at 12.9ms against 3-3.6ms on reruns, one browser pause in 960 samples. A ground slow on every frame still fails (a 9ms stall added to it read 11.4ms). The Blossom's pink far wood met the green field in a straight cut on about one hole in eight (a step of up to 87 against a limit of 60); the wood's foot now fades into the field (worst 48 over forty holes). |
| `hazards` | No bunker or pond touches a putting surface, and no hole is left without a bunker. Both are rejections that have to keep working, and they pull against each other. Forty holes of every course, each hole checked to be on the course it claims: it used to walk holes 1 to 40 after picking a course, which are all on the first event, so it checked one course thirty times. An island green's lake is the one exception, and is held to the opposite rule: water in front of the green, behind it and on both sides. |
| `icons` | Every icon id a list asks for exists, every drawing is 12×12, and no two things in the game share one. Icons were once keyed off the stat each thing moved, so one golf ball stood for seventeen different things. And every drawing reaches the screen at a size it divides into: they are all 12×12, so 12, 24, 36 and 48 give every source pixel the same number of screen pixels and nothing else does. Seven other sizes were in use, and two were not even square — the locker's equip button squeezed its sprite to 7.8 wide by 13 tall, because the button is a flex row and the image had nothing holding its width. The locker shows one slot at a time and only draws that button on a club you are not carrying, so the setup opens enough bags to be sure of a spare and turns the locker to the slot holding the most of them; left to chance it swept an empty locker about one run in ten and proved nothing. The home screen icon has to be 180×180, an actual picture, and crisp: it is painted on a 36-pixel grid and scaled by exactly 5, so any smoothing shows up as blended 5×5 blocks. Every shot icon has to be drawn centred in its own 12×12 grid, within a pixel each way: the boxes are centred on the grid, so an off-centre drawing is an off-centre icon (Thunder Drive's bolt lived in the top-left corner). Since the menu icons were redrawn (the user asked for icons that fit what they stand for): no two ids may hold the same drawing, since a copied picture under a new name passes the one-id-each rule and still shows one picture for two things; and every heirloom, shown large when it is found, has to be a shaded drawing of at least thirty pixels with a second tone in at least six, not a flat cut-out. Negative tested by copying one heirloom's drawing to another and by flattening one. |
| `economy` | The affinity cap holds on **both** channels. Affinity feeds damage and prize money, and the cap was once applied to only one of them, so a stacked build multiplied gold without limit. Also the cup target: it has to be harder every cup and may only stop moving at a card of nothing but Aces, or a card that beats it once beats it forever and cups become a free exponential into retirement legacy. |
| `menus` | Five tabs, both sub-navs, the folds, the pull tab, and the skill cooldown bars. The shot book and trophy room lost their own tabs, so the old view names still have to route — and the cooldown bars are driven off the view name, which is exactly how they stopped ticking when the shot book moved.  And the first cards open sooner: five events a card had a new player looking at "0 of 5" for 47-49 minutes before Card 2 opened. Cards 2, 3 and 4 open after 2, 3 and 4 events on the card below, then 5 as before. The Tour tab in four sub tabs (Card, Season, Major, Signature), which the user asked for to cut the scrolling: each shows its own sections and no other, and a new card waiting opens the tab on Card whatever was looked at last. Each wager's Guide button stays a small button (the Field Guide's grid once took its class and stretched it to 96 pixels, crowding the name); negative tested with the grid on the class again. |
| `devmenu` | The dev menu writes straight to state with no cost and no undo. It must not be reachable by a tap: the course name is the most prominent text on screen and the easiest thing on it to hit by accident. Every dev button is then pressed once and must not throw or leave the stats non-finite: the ball, wager and currency buttons had double quotes inside a double-quoted onclick, so fifteen of them had never worked. The newer buttons (dailies, named sets, trophy and honours resets, Card 1, sovereigns, the stake override, mastery, the bond, Golden Hour and the gallery) are checked for doing what they say. The menu is in folds (the user asked for it tidier), every button inside one, and a fold left open stays open when the menu redraws after a press. The wildlife fold (the weekly hunt and another week's, the Guide at a hundred, the ace plaque, the tag and animal-call switches) is checked to do what it says; negative tested with "next week" doing nothing. |
| `wagers` | Each of the four says what one entry is WORTH, in what that currency buys — and the check plays each contest out and compares, because a projection nobody has measured is just a number. The first cut of it was 5x over on the Island Green: it priced the pot at your bank target as though you always got there, and you reach it about one run in ten. Bounds are per contest and come off repeated runs, because the Long Drive settles at once and the Island Green needs seven hundred samples. Every reward in the wager book is priced off how far past its Tour Card a run gets, never off the raw floor number. The raw number climbs about two rungs a card on its own, and two of the four contests used to score themselves off their own last run, which is a loop rather than a drift. The Vault's gallery rope has to run to the bottom of the frame with the camera a third of the way down, and the check draws that floor's own ground first: props are cut against the crests the ground march records, and it used to cut them against whatever hole the live frame had last drawn. Also holds the away model to the live one: an away hole has to take as long as the average live hole, and — since the pace, the purse and the drop rate all used to be read off whichever hole you parked on, and each of them carries the par, the closing hole, the Sunday and the weather — every one of the seventy two holes of an event has to give the *same* away rate, measured across a 7.5× spread of single-hole purse. The measure walks the golfer over those holes, so it also has to put him back, including when it throws part way through.  Six contests now: the Scramble (provisionals) and the Twilight Putt (tempo) joined the four. The entry-worth comparison gives its test bag 1.6 provisionals and three swings a second, because at zero provisionals the Scramble plays one ball and a projection that ignored them passed, and at a fresh bag's tempo the Twilight Putt fits a dozen putts whatever it thinks. And the Sponsor Exemption is priced off the entries it refills: at six tickets for eighteen entries the runs it bought now and then earned the next one (0.38 a run against 0.33). |
| `progression` | The five progression systems do not repeat each other. The Range, the attributes, the talents, paragon and the trophy room all used to sell "+% swing power". Paragon may not name a stat another system sells, every paragon line has to be wired to something outside its own table, every trophy has to compound and cost more per level than it gains, and every attribute has to have a milestone at the end of it that a single career cannot afford four of. The talent trees are held to the same rule, both ways round: no talent may name a stat sold on a ladder elsewhere, every talent key has to be read outside the tree, and every key `career()` hands out needs something that hands it out — which is how `cond` turned up, read every hole and granted by nothing since the trees were written. Seven talents are measured moving live and Sponsor Eye is measured on four hundred drops. Also that no id lives in two tables at once: five do, every one of them a key in somebody's save, so they are listed rather than forgiven and a sixth fails.  Honours pay sovereigns: every one-off in the 7 / 13 / 130 bands, every repeating honour 3-13 a step. Unlocking pays once; checking again pays nothing; a save from before honours paid is back-paid once for what it had already earned, and its repeating honours count from where it stands rather than paying 25,000 holes as 250 Steady Hands; a new career is paid nothing for counting from zero. |
| `shop` | The stage buttons first: the shop under the settings gear under the readout, the Trophy Room under the shop and drawn as a medal (the user asked for no trophy), and auto-climb just right of the readout, centred on it (level with its foot, the user saw it as dropped below the box). The readout used to be as wide as its words, which change every second, so the check writes the longest words the readout can show into it and the button must not move: letting the readout size to its words again moved it 20px. Every tab is a rack of tiles, each with art and a price. The pro shop is a storefront with no store behind it, and the first checks here keep it that way: it has to say so on every tab, it must never render an input, a form or an iframe, and a pack must grant without taking anything. Then the shop working: a bag honours the rarity floor and the pity counter it advertises, a bench line stops at ten and is read somewhere outside its own table, each pack is better value per dollar than the one below it, and nothing outside the shop ever pays a sovereign. The Style tab sells looks for sovereigns, caddies included: every outfit and skin has a caddie to match at a third of its price, and he wears its colours: wearing every outfit and trail must leave derive() identical, each is charged once and worn free after, ten sovereigns buy nothing, a save wearing a look it does not own loads in the plain one, and the chosen outfit has to reach the golfer's own pixels — including the shirt's darkest fold, a letter in the sprite that had no colour and left holes in his back. |
| `readouts` | The five places the game answers a question instead of listing numbers. The item sheet has to say what a club would do to the carry *before* it is swapped in, and the preview swaps the club in to measure it, so the one thing it may never do is leave it there — it is asserted across every spare in the bag and through a throw mid-measure. The away card has to show what came of the time rather than a wall of zeroes, and when you have been gone far longer than the caddie is good for it has to own up to both numbers — nine days away used to be reported as "12h away", which is not where the week went. The Range used to carry a summary line at the top naming the next rung in reach, and then each row said "unlocks when you have" its price; the user asked for that gone too, so now no rung says when it unlocks (broke, rich or capped), and the price shown on each button is the price it charges, grey until the purse covers it. Every buy button, at every multiplier, has to charge for the number it names: on Max the quantity floors at zero while the price quotes one regardless, so a rung you could not afford read "×0" over a price of 1.20K — an offer to buy nothing for twelve hundred. The retirement screen has to show what a card is worth *before* retirement opens, what one more Tour Card and one more cup would each add, and what the result buys in a trophy room whose prices climb. The honours list has to open on what you are closest to rather than on whatever was typed first, and say so at the top and on the button.  And what is running when you leave: derive() reads whatever is live, so a twelve-second skill buff fired on the way out paid 2.5x on twelve hours away, an eight-minute perk 5x and an hour of Double Purse doubled all twelve. Perks now sit the absence out and resume, buffs lapse, Double Purse runs on the clock and pays its share, and the free gift and members' daily count the calendar rather than only time with the game open. The climb cases use plain clubs: rolled at random, an element that matched the course made the "behind" bag outdrive its card on some holes, and the check failed one run in ten on a setup that was not what it said it was. The yardage follows the ball on screen: it holds while the golfer walks to his ball and drops as each shot lands, and never reads less than the swings underneath have taken. It used to follow those swings, several a second, and ran down while he walked with nothing in the air. |
| `daily` | The two things that run without you. Auto-equip asks `derive()` rather than reading `itemScore`, which is a sort key that discounts the affixes it cannot price and knows nothing about sets. Measured over **four dozen** lockers of 120 drops each, from a fixed seed (at two dozen unseeded the purse figure ran -2% to -22% run to run and failed once on a change that never touched gear; seeded at 48 it reads -12% to -19% across six seeds), the greedy sort key comes out behind on both axes every run — at one locker that figure changed sign between runs (greedy 136% ahead one time, 64% behind the next) and the printed number taught you nothing, which is the opposite of why it is printed. So it takes a swap only when it is better on one and worse on neither, it has to be genuinely inert when off, and it may never lose a club. The stake of the day rotates strictly off the wall clock: stored in the save, a reload would reroll it. Its multiplier is checked by running one contest twice off the same state and the same random sequence, so the gear roll, the ticket and the experience have to come back identical and only the money moves. |
| `layout` | Nothing sticks out past the edge it is inside, measured across five screens, four shop tabs, the Trophy Room's three pages and three sheets — about 2,000 boxes. A grid item will not shrink below its own min-content unless it is told it may, so a club with a long name pushed the locker row's middle column to 231px where only 222 was free: the row overran its own right padding and squeezed the button until the word UPGRADE was cut in half. Also that the away card's three tiles put their captions on one line — one of the three is in a bigger face, so left to flow from the top it set the row height and the other two sat above their own middles. Both are invisible to every other check here: the numbers are right, the rows are all present, nothing throws. You have to measure the boxes.  It also reads every piece of text on every screen for two faults that a column is free to cause: a unit spelled as two ordinary words ("55 per cent" broke after "55 per", leaving "cent" alone on the next line) and a figure that can be parted from the unit it carries. It asks whether a pair CAN break rather than whether it did at some width — the first version measured where lines fell at four widths, and unbinding "+1.2% swing power" again went straight past it, because no tested width happened to end the line there.  And a phone on its side: the column gave the field half of a 360px-tall screen and pushed the tabs off the bottom, so the menu was only reachable through the pull tab. At 740x360, 844x390 and 932x430 the field and the menu have to sit side by side with all five tabs on screen, and turning the phone with the menu pulled up has to bring back a field that is being drawn, not a frozen picture. The numbers that float over the golfer are driven through 600 fast swings of up to a few billion yards and every live pair measured at its real text width: the old nudge assumed short numbers and put 13,252 overlapping pairs on screen. The bottom right corner, from the bottom up, is the pull tab, the hole map just above it, and the weather words standing on the map: the words end above the map (or above the tab with no map), the map sits within 24px above the tab, and their right edges line up. It draws one real frame before measuring, since that is when the map is placed, and requires the map on a 400 wide phone so those rules are really exercised. The wind and weather words over the map are on the page now, in the interface's sans serif (the user asked): measured by their own box, the lowest ends above the map and their right edge lines up with it. |
| `legibility` | Every button can be hit and every word can be read, on a 360px phone. The grey used for every caption, unit and inactive tab stood at 3.4:1 against the panel and 2.5:1 on a raised button, where small text wants 4.5:1 to be read in daylight — and it is most of the text in the game. The "?" help buttons were 17px square, and the multiplier row, the small action buttons, the auto-equip toggle and the menu handle were all under 24px tall, the smallest target WCAG calls tappable. Measured across every tab, sub-tab and shop page: no target under 24px, no button without a name, no text under 4.5:1 against what is actually behind it. |
| `settings` | Sound, backing up and loading a save, erasing it. The save lives only in the browser, and Safari clears a website's storage after seven days away unless it is on the Home Screen; there was no way to take a copy, and erasing lived in the developer menu. A save code has to round-trip, compressed and plain; a bad code has to be refused with the save untouched; loading a code keeps the save it replaced; sound switches off and stays off, and plays nothing through a catch-up; the course sounds like one (the two recordings, the strike and the ball in the cup, decode and play; a holed ball is the cup alone, with no gallery (the applause after every hole never stopped on a fast bag, so it was taken out); birds sing on a fine day; and if a recording cannot decode, the synthesised sound still stands in for it); the music decodes, plays one track at a time, loops by starting the next play under the end of the last, and stops with Music or Sound off and through a catch-up; and the Home Screen tip shows once, on an iPhone, after a real session. All four recordings have to decode, the two music tracks included: it used to wait for three and then ask for exactly three, so it failed whenever the second music track happened to finish decoding first. Crickets on a dry night (the user asked, with birdsong, which was there already): heard at night and never by day, no birds at night, neither in the rain. The putt's recording now decodes with the others and a putt plays it. |
| `sets` | Named club sets — Heritage (purse), Stormforge (tempo), Twinline (provisionals), Caddie's Kit (gear luck and wager haul). A Rare or better club drops as part of one at SET_CHANCE for its rarity and nothing below Rare ever does; a set piece carries its maker's name; every tier pays exactly its table from one piece to six, through the same gear stats as every other bonus; and a club tagged with a set this build does not know loses the tag, not the club. |
| `challenges` | Daily challenges: three a day off the same clock as the stake of the day, each paying sovereigns, with a bonus for all three that grows on a streak. The three are seeded by the date, so a reload cannot reroll them; every one in the pool comes up within a month, and the level-gated ones never come up early. Progress counts from the start of the day, so a long save does not clear them all on load. Each pays once however often the tick runs; the streak builds, caps, and resets after one missed day; a mangled daily in a save is rebuilt. Every challenge in the pool has to be reachable by a player who has stalled: "Win a cup" was taken out after a six-hour idle run won none, because a day that cannot be finished breaks the streak for nothing the player did. The progression check marks the day's three done before counting honours, or reaching 250 holes would pay a "play 120 holes" daily on top. None may fall in the first five minutes of a brand-new save: the first pool was sized by eye and 'Card 30 birdies' went in three and a half; the pool is now sized to about half an hour of play each, off measured rates per hour. Today's three are on the Today page of the Trophy Room, and the check reads each one there by name: it used to look for the word "Today" in the honours, where they no longer are. Five minutes of a brand-new save is now judged over twelve starts, not one: a single start swung with the dice and with the week (pinned to Island Green, its one start found 12 Rare clubs, which about one start in twenty does), and it hid 'Card 70 eagles', which a third of fast starts cleared in five minutes; that daily is now 100. A daily fails if more than three of twelve starts clear it or a typical start is four fifths of the way through it (negative tested with the old 70, 4 rare clubs, 40 birdies and 30 holes). |
| `pacing` | The first two hours played the way a person plays them, over eight seeds: buy the cheapest Range rung whenever possible, auto-equip clubs, spend attribute points, and let the game's own auto-climb move up. At least 60 holes every twenty minutes, at least 40% par or better in every window, and three cards opened; a run that buys nothing must finish three cards below every run that plays. With holes fixed to their card these rules are absolute: a new golfer sprints 260-300 holes through a card they outdrive, and one who has climbed to where they belong plays about a hundred at par pace. It caught an armour wall on closing holes that read 0% par or better. Written after one idle run read as a stall (birdies 146 an hour down to 12) — that run bought nothing, and a card's holes grow over its events. A 70% pace rule failed on an eager climber with unlucky gear and was chased to that, not loosened blind. It catches a handicap floor at par at once but not a tenth of the purse: for two hours a playing golfer outhits the card whatever the economy does, so the handicap, not income, sets the score. When scoring moved a band (birdie is now the floor), its birdie-or-better rule failed at 42-52% for an eager climber behind the card, with the pace rule holding: pars, not a stall. The rule moved a band with it, to par or better, counted once per finished hole (the Tour tab's climb preview reads the same table and double-counted 2%). Sixteen seeds, not eight: the eight passed while other sets of eight each held a player at four times par for twenty minutes, because auto-climb judged the next card by the luck of the round it was in. |
| `rival` | One named rival per event, set off your recent form. The same golfer and total all event, made on the first hole whether or not the Tour tab is opened (made only when the tab drew, a player who never looked had no rival). Beating them pays once; a loss, a tie, or an event resolved during a catch-up pays nothing and teaches the form nothing. A mangled rival is rebuilt. And they have to be beatable about half the time: eight seeds of three hours played for real must land between 40% and 65%. Centred on form alone it measured 35% while a card's holes grew across its events; a 3% ease brought it to 52%, and on fixed holes it reads 48%. |
| `skins` | Skins and balls that do more than change a colour. Each one's effect has to draw something its colours alone do not (taking the effect off must change the frame, or a 3000 sovereign skin is a recolour); each skin's golfer must average under 1.5ms a frame over 300 draws — the Divine skin first measured 2.3ms, redrawing him strip by strip twelve times for its glow, and now stamps one silhouette at 0.84ms; "Try it" wears a look for ten seconds, spends nothing, writes nothing to the save and takes it off; and the Style tab lists every look once, each with its own picture. Midas failed the first rule between its shines and was given a constant touch rather than the check a luckier moment. And every trail has to be seen: a ball in flight must paint at least fifteen times the pixels the plain ball does, at no more than one and a half plain golfers (four times let a small duck over a few blue dots through at 10.7x). And no trail may be drawn below the golfer's feet, measured live over eight seconds of play: the camera walks on while the ball is up, and the tail reached up to 83px back past him to the tee he had left, as if the shot came from behind him. A frozen, hand-set launch never showed it. The colour trails were three one-pixel dots behind the ball, and the Rainbow painted 6 pixels to the plain ball's 6; nobody could tell it was on. Its bands, once drawn, were first stacked down the screen along a flight that runs up it, and landed on one line. Between shots he walks: every look has to stride (two phases of the walk differ from each other and from him standing) inside the same 1.5ms, with his fairy caddie drawn beside him. With the Divine skin on both of them the frame first measured 1.51ms; the caddie takes no beam of his own from the sky, and his outline, which never leans, is cut once and reused. A caddie in a skin has to draw its effect too. Between shots he walks away from us, from behind, the club hanging in his hand. Every special club (glow, stripes, a rubber chicken, a light saber) has to draw more than its colours, at address and through the swing where its arc shows, inside 1.5ms. The ball at rest, teed up or lying where it came down, has to be the ball he has on (and the dearest trails, the Seraph, Hellfire and Ascension Wakes, rest in their own look too). The Style tab shows one rack at a time (Golfer, Caddie, Clubs, Balls, picked along the top), and every look has to appear once across the four, each with its own picture; the icon, layout, legibility and titles sweeps visit all four. Every cost is the quickest of five blocks of frames: one average over the lot put a look over its budget one run in three, from pauses in the browser, on the code before and after a change alike. A skin's golfer is timed against the plain golfer instead, forty frames each in turn, seven times, the middle ratio held to fifteen: the bound was 1.5ms, and in a container twice as slow the untouched Divine took 1.9ms (the caddie's spins, drawn turned, also landed in some blocks; he is kept still now). A trail is timed the same way, a ball against the plain golfer, the middle ratio held to one and a half: alone against 0.5ms it failed two runs in three on a busy machine, a different trail each time (the dearest draw 0.9 of him; one made 0.4ms dearer goes to 1.9 and fails). Negative tested with the Divine's old strip-by-strip glow (23 plain golfers) and the Glitch's copies strip by strip (16 to 32). Walking, the Glitch, Void Walker, Midas and Stormcaller copies of him are drawn whole now, as he is: the Glitch walking beside its caddie was twelve plain golfers. |
| `scoring` | The shape of a round for a golfer who plays, over eight seeds of two hours: birdies 20-45%, eagles 20-45%, pars 8-30%, albatross or better 5-25%, bogey or worse under 12%, nine goals won 25-75%, and no one score over 45% of holes. Holes are fixed to their card now, so a golfer's score says how far ahead of the card they are: auto-climb moves them up once they can birdie the next card, and a round averaging 2.5 under a hole opens the next card at once, which keeps albatrosses at about 14%. Before holes were fixed: The handicap floor used to be 0.34 of par time, an Eagle, and a golfer ahead of the card carded eagles on 67% of holes and won 92% of nine goals, so score said nothing. The floor is 0.52 with par times cut to two thirds (same holes, same time, read a band worse), score pay raised 1.27x and cups reset, so income, level and cups hold (16 seeds before and after). Putting the old floor back fails it at once. |
| `retire` | Where retiring puts you. With holes stretched to the golfer, retiring sent everyone to Card 1; with holes fixed to their card that would mean blazing back up through cards you outdrive by miles. So a retirement lands on the highest card where a fresh par four still comes in at a birdie, measured on the golfer after the Range resets, capped at the best card reached and floored at the Chronoglass; the retire sheet names it. And a save from before holes were fixed is moved once, on load, to the card its golfer matches: loaded as it stood, a Card 8 golfer would have met holes seventy times longer than the day before. The flag that says a save has been moved lived only on the live state at first, so a reset to the defaults dropped it and the next reload threw the golfer back to hole 1 — the save check caught it, and this one now asserts it too. |
| `names` | Everything lives in one file — markup, styles, script, and the markup the script writes as strings — so a name is global three times over, and the same name meaning two things has cost this file a day on three occasions: `#crest`, `.empty`, and `#hud`. `#hud` was the instructive one: a rule with `inset:0` left behind when the old stage HUD came out, doing nothing at all until a new left-hand column took the name, inherited `right:0` and `bottom:0`, and stretched itself over the whole stage. So: no `#id` rule without an element under it, no id the script asks for that is in no markup anywhere, and no id on two elements at once. It found seven live dead writes on its first run — four of them in `renderLive`, which runs every frame. |
| `save` | A save written by an older build still loads. `migrate()` is the only thing between a format change and somebody's progress, so it gets a save with junk in it, keys that no longer exist, and keys that never did. It also gets fifty points spent on the ten talents this build renamed: they have to come back as unspent points with the counter set, because deleting them silently is how a save loses a career to a balance patch.  And coming back from another tab or app: the browser stops the frame loop while the page is out of sight and the first frame back clamps to a quarter second, so ten minutes away used to be worth 0.25s of golf. Thirty seconds away has to be played out at full pace, two hours has to raise the same away card a reload would, and a second return straight after has to pay nothing.  Every club that survives the repair has to score to a real number: "rarity at least zero" let a rarity of 99 through, the save loaded, and the first sort of the locker threw — while this check, which had put that very club in the bag, passed.     if (!(n >= 0)) throw new Error('gold came back as ' + n);
```js
    return ['gold ' + n];          // shown next to PASS
  }
};
```

array of short strings to report alongside a pass — a check that only ever
prints PASS teaches you nothing about the direction things are moving in.

`DEV.course`, `DEV.set`, …); use it to get to a state rather than playing to it.
Note that `Scene`, `S`, `B` and `DEV` are script-scope bindings, not properties
of `window`, so reference them bare inside `page.evaluate`.
